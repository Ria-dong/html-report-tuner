# HTML Report Tuner

给任意一份已成型的 HTML 报告（自己做的、同事做的、别的 AI 做的都行）现场生成一个独立的**调整工具**——不用每次改颜色/挪模块都重新找 AI 对话，工具生成后在浏览器里就能自己玩。

左侧是参数面板（Style Control Panel），右侧 iframe 实时预览目标文档。所有改动先在工具里调到满意，点"保存"才导出成新文件；原始文件自始至终不会被覆盖，也不会上传到任何外部服务——纯本地 HTML，离线可用。

## 这不是什么

不是一个"写死代码、套用在任意 HTML 上"的通用脚本。核心方法论是**每次现场读、现场理解、现场生成**：颜色 token 怎么分组、模块边界怎么划，都需要调用这个 skill 的那次会话里，AI 真正读一遍目标文档、按它的实际写法做判断。`templates/tuner-shell.html` 只提供通用的交互"壳子"（面板 UI、拖拽引擎、撤回栈、保存导出），`scripts/build_tuner.py` 顶部的 `CONFIG` 才是每次真正需要重新填的部分。

## 功能一览

- **颜色**：自动探测或改写出 CSS 变量，取色器实时预览；双向"定位"——点颜色看它在页面上哪、点页面看它是什么颜色，高亮色自动取当前背景的互补色。
- **配色卡**：17 套预设（5 套常驻展示 + 12 套收在"更多"里，深色底/浅色底各半，商务/科技/高级三种气质），一键切换整套配色，数量不够自动插值、数量超出自动找色相空隙插新色，不会出错或重复。
- **模块拖拽**：按"重复兄弟结构"规则自动判断模块边界，拖拽排序用 FLIP 做平滑位移动画，小幅拖动只换一格、大幅拖动跟手到底。
- **文字编辑**：一键切换整页可编辑。
- **撤回**：改色、配色卡切换、模块拖拽/新增，统一进一个线性撤回栈。

## 怎么用

在 Claude Code 里触发这个 skill（自然语言，比如"帮我做个调整工具"，或者把目标文件路径带上），跟着 `SKILL.md` 走六步：读颜色 → 文字编辑（不用管，壳子自带）→ 判断模块边界 → 填 `CONFIG` 跑 `scripts/build_tuner.py` → 用 Browser 工具实测 → 把产出的 HTML 发给用户。产出默认落在 skill 目录下的 `output/` 文件夹。

## 目录结构

```
html-report-tuner/
├── SKILL.md              # 完整流程、硬规则、已知局限——每次调用前要读的那份
├── templates/
│   └── tuner-shell.html  # 通用壳子：面板UI、颜色数学、拖拽引擎、撤回栈、极光背景
└── scripts/
    └── build_tuner.py    # 构建脚本，CONFIG 是每次要重新填的部分
```

## 已知局限（如实列出，不是藏着）

- 颜色：浅底徽章/透明度变体类的衍生色不纳入调整范围，固定跟随原值。
- 模块：只做一层展开——嵌套两层以上的重复结构（比如小节内部的引文卡片网格）不会被拆开，整体算一个模块。纯内联 `flex` 分栏、既没有可识别 class 也没有 border/background signature 的布局，不会被自动拆开。
- 拖拽重排后，文档里的页码、章节编号等"位置编码"内容不会自动重新编号。
- 文字编辑不进撤回栈（细碎到逐字符，没法做有意义的"一步"切分；浏览器自带 Ctrl+Z 在可编辑区域本来就管用）。

详细说明、每一条背后的实测证据，见 `SKILL.md`。
